# AGENTS.md — Developer guide for Marka

Read this before changing Marka. All code, comments, commit messages, and documentation on disk must remain in **English**. Chat with humans may be multilingual.

End users should read [`README.md`](./README.md).

---

## What Marka is

**Marka** is a native, lightweight Markdown editor for macOS. You edit like in Word, the file stays clean GitHub-Flavored Markdown, and the pages on screen match print and PDF (A4).

Hard product rules (from the original spec):

- Swift + AppKit (SwiftUI only if AppKit cannot do the job). TextKit 2 for layout — note the editor currently runs on AppKit's **TextKit 1 fallback** (`textLayoutManager == nil`) because `layoutManager` is touched; code that measures text must handle both (see `MarkdownTextView.inlineCodeBoxRects`).
- **No WebKit, Electron, or JavaScript.** No `WKWebView`.
- macOS 14+ (deployment target 14.0, so the compiler rejects newer APIs), Apple Silicon first, universal builds for releases. Liquid Glass only through runtime checks (`GlassChrome`); SF Symbols referenced by name must exist on macOS 14 or have a fallback (`DocumentWindowController.sonomaFallbackSymbols`).
- App bundle ≤ 8 MB. Typical 20-page document ≤ 60 MB RAM. Launch under 0.5 s.
- Minimum dependencies. v1 uses a range-accurate parser in `MarkaCore` so styling maps 1:1 onto UTF-16 ranges in the source. Do not add packages without a written reason.
- MIT license.
- **The `.md` file is the source of truth.** Saving must not rewrite lines the user did not edit. Unedited documents round-trip **byte-identically** (BOM and line endings included).
- What you see on the A4 pages is what PDF and print produce (one layout).

Out of scope: cloud sync, collaboration, plugins, Windows, Linux. Git is limited to Publish (rule 30) — Marka is not a Git client (no branches, pulls, merges or conflict resolution). Code syntax highlighting, LaTeX math and Mermaid diagrams were added on request — natively (rules 21 and 28), never via a web view.

---

## Critical toolchain constraint (no full Xcode)

Marka must compile and test with **macOS Command Line Tools** (`swift build` / `swift run`). Full `Xcode.app` is optional.

1. Do **not** use SwiftUI / Observation macros (`@State`, `@Observable`, `@Model`).
2. Do **not** import `XCTest` or Swift Testing macros (`@Test`, `#expect`).
   - Unit tests: `Tests/MarkaCoreTests/main.swift` → `swift run MarkaTests`.
   - UI tests: `Tests/MarkaUITests/main.swift` (off-screen AppKit, no XCTest) → `swift run MarkaUITests`.
3. `Package.swift` uses `swift-tools-version: 6.0`. Keep `MarkaCore` `Sendable` where it crosses isolation. AppKit types stay on the main actor.

## Architecture invariants

1. **One source string.** `NSTextStorage.string` is the Markdown. Styles and hidden markers are display attributes only. Never replace the source with RTF, HTML, or attachments that drop syntax.
2. **Identity save.** `FileCodec.encode` returns the original `Data` when the normalized string is unchanged.
3. **A4 pagination.** One text container whose width is the content area. Inter-page gaps (bottom margin + grey gutter + top margin) are `NSTextContainer.exclusionPaths`. Forced breaks are `<!-- pagebreak -->` plus an extra hole to the bottom of the current page. The page count follows the **content** (`PagedEditorView.contentPageCount`): through the last non-whitespace character's line fragment (paragraph spacing included, so a table's overlay space counts) plus the caret's page while blank lines are typed at the end. It shrinks when content is removed, and trailing newlines never add an empty last page.
4. **WYSIWYG markers.** Markdown delimiters stay hidden in WYSIWYG (near-zero font, clear colour). Clicking must not reveal `*`, `_`, `` ` ``, or quotes, and must not restyle the whole document (that jumps layout). Source mode (`⌘/`) shows the raw Markdown.
5. **Images and file references.** Every picked / dropped file goes through `FileReference` (images, other dropped files, the link card's Choose File): inside the document's *home* — its git work tree while tracked (`trackedRoot`), else its folder — it is referenced relatively (`../` allowed; spaces, parentheses, `<>`, `%` escaped) and `GitService.trackIfNeeded` adds it when git does not track it (never `git add` a tracked file: that would stage its edits). Outside, a sheet asks: **Copy** (editable name relative to the document, images default to `assets/<name>`; `..` and absolute parts are stripped, an identical file is reused, a different one gets `-1`, never overwritten; the copy is git-added) or **Use Original Location** (absolute path, with the warning that it breaks on other computers). Untitled documents use absolute paths. A target without a scheme is always a path relative to the document (an implicit `./`, as GitHub resolves repository links); only real schemes (`https://`, `http://`, `mailto:`, …) are web links — Marka no longer guesses that `example.com/x` is a website. **Pictures in table cells** (`![alt](src)` and `<img width height>`, found by `CellMarkdown.cellImages`): shown at their natural size, never wider than the column (read from `pictureMaxWidth` at draw time — columns are measured after the fields exist) nor taller than 240 pt. Rows have per-row heights: `PagesTableView.layoutMetrics` (static, used both for drawing and for `measureTableSpacing`) measures columns from what cells *show* (pictures, text without Markdown; long paths no longer widen columns) and gives each row its tallest picture + padding; `PageLayout.flowTableRows(rowHeights:)` / `TableFlow.Row.height` carry them through pagination, slices, grid, grips, drop lines and PDF. Cells edit in their own field editor (`MarkdownCellFieldCell` → shared `CellFieldEditor`, TextKit 1): `CellMarkdown.styleSource` hides the image Markdown, reserves its width and line height, and the editor draws the picture (`.markaCellImage`), so a cell looks the same while edited; the caret never lands inside hidden image Markdown (it snaps to the edge). Clicking a cell's picture commits the cell and opens the image card anchored on the cell (`pagesTable(_:clickedImage:…)`); `MarkdownSyntax.tableImages` / `image(at:)` let the card's edits (source, options — centre is plain `<img>` in a cell, a `<p>` would break the row — remove) work inside tables. Undo / Redo in a cell use the first-responder field editor (not `window.fieldEditor`). Images inserted while a table cell is being edited go into that cell (`insertImageInCell`, inline `![alt](path)`); cells draw them as pictures fitted to the row (`CellMarkdown.attachment`, paths resolved against `PagesTableView.documentDirectory`). **Display (GitHub look):** `MarkdownSyntax.imageLines` finds lines with images (not in code or tables). WYSIWYG hides every `![alt](src)` group; a line of only images (link-wrapped badges included) collapses like a table (`collapsedTableParagraph`), other lines keep their style with extra `paragraphSpacing`. The reserved height comes from `measureImageSpacing` (keyed by line start, merged into the bounded `relayout()` loop like tables and drawings); `ImageBlockView`s sit in it (`imageTop`: the collapsed line's y, or below the line's last used fragment) — natural size, capped to the column width and a page's height, flowed side by side and wrapped. Pictures come from `ImageStore` (files cached by path + modification date; http(s) fetched once in the background, `ImageStore.didLoad` relayouts); missing ones draw a placeholder with the alt text. `drawImages` puts them in PDF / print. Clicking a picture opens `imageCard` — a `LinkCardView(imageMode: true)`: path field (commit = `MarkdownEditing.setImageSource`, alt and title kept), Choose Image… (through `FileReference`), Open, Copy (absolute path / URL), Remove (`MarkdownEditing.removeImage`; an image-only line goes with its newline); any selection change hides it. Paths resolve with `Hyperlink.destination` like links (`%20`, `<…>`, `../`, absolute); the Markdown line stays in the file.
6. **Fenced code.** WYSIWYG keeps the source fences; padding is paragraph indent/spacing. A rounded GitHub-style fill is drawn *behind* the text view (clicks pass through). Small round **glass** icons (22 pt, SF Symbols, no border tile; `NSGlassEffectView` on macOS 26+, a translucent material on 14/15) hang off the block's top-right corner; only the icons take hits (`hitTest` uses superview coordinates), and the text view keeps the pointing hand over them (`MarkdownTextView.pointerHotspot`) because it would otherwise re-apply its I-beam on every mouse move. Copy writes the inner text with a single `setString`; block quotes get the same icon (copies without `>`). Shell fences (`sh` / `bash` / `zsh` / `shell` / `fish` / `ksh`) and Python fences (`python` / `python3` / `py`, `ShellRunner.isRunnable`) also get a Terminal icon that writes an executable `.command` file (`ShellRunner`) which `cd`s to the document directory and opens in Terminal.app; Python code is saved as a `.py` file run with `python3` (not piped, so `input()` works). The `.command` file deletes itself and the `.py` on exit (`trap … EXIT`) and adds nothing else by default — Terminal keeps the window and output anyway; Settings → `waitAfterScript` (default off) appends a ✓ Finished / ✗ Exited with code N line, waits for any key (`read -k 1`) and exits with the script's status. Unit tests run the generated files with zsh. A block that crosses a page break is clipped to each page's content rect (`PageLayout.pageContentPieces`).
7. **Links.** WYSIWYG shows only the display text (blue, underlined, pointing hand), including `[`code`](url)`. Do **not** set `NSAttributedString.Key.link` on the glyphs — that steals clicks. Clicking a link puts the caret in the **label**; the link and image cards' icon buttons are in `pointerHotspot` (`LinkCardView.buttonContains`) so they keep the pointing hand over the text view; the Word-style card — one 30 pt row, 300 pt wide, inside the zoomed page: address field in the document's body font size (`fieldFontSize`), divider, borderless 22 pt icon buttons with 10 pt symbols — the code block icons' size (`LinkCardButton`, hover fill; the icon is an `NSImageView` filling the button, `bezelStyle = .shadowlessSquare` — never NSButton's own image drawing: `NSButton(frame:)` is a push button that lays its image out in the bezel's content area, and a fixed-size image was cut at the top and bottom on screen) Choose File… (`folder`), Open (`arrow.up.right.square`), Copy (`doc.on.doc`, checkmark feedback like code blocks), Remove Link (the `link` symbol with a drawn slash — SF Symbols has no unlink glyph) — shows the address without taking first responder; ⌘K focuses the address field. ⌘-click and Open resolve via `Hyperlink.destination` (local paths percent-decoded, `<…>` unwrapped, resolved against the document folder): local `.md` files open as a new Marka **tab**; a missing `.md` target is created empty (missing folders too, never overwriting — `Hyperlink.createMarkdownFileIfMissing`); other files and `http(s)` / `mailto` open with the system.
8. **Inline formatting.** `**…**` / `*…*` may wrap links and inline code (`**[readme](README.md)**`, `**`Marka.dmg`**`, `*`Marka.dmg`*`): only the delimiters must be free in `MarkdownSyntax.parseInline`. Bold/italic are applied in a last pass that *adds a trait* to the existing font (monospaced bold, bold links). Inline code is a GitHub box: rounded (4 pt), `rgba(175,184,193,0.2)` / dark `rgba(110,118,129,0.4)`, 90 % code font; the hidden backticks carry the horizontal padding as kern, and `MarkdownTextView` draws the boxes (`.markaInlineCode`) behind the glyphs.
9. **Tables — display.** A table looks exactly like GitHub's: bold header, 1 px `#d0d7de` grid, even data rows striped `#f6f8fa`, starting at the content's left edge, and no permanent chrome (no column letters, row numbers, or +/− chips — `PagesTableView.hasOnlyGitHubGrid`). WYSIWYG collapses the GFM source (near-zero line height, clear glyphs) and paints the opaque table over that hole; the source is re-hidden in a **last** `StyleEngine` pass, because inline passes (code font, link blue, bold colour) would otherwise leak cell text around the table. Cells render their inline Markdown (`CellMarkdown`, `MarkdownCellField`: bold, italic, strike, code, links) and switch to the raw source while edited. A table that does not fit the rest of the page is split into one `TableSliceView` per page (`PageLayout.flowTableRows` + `tablePageSlices`) with the header repeated. Table spacing is folded into the bounded `relayout()` loop — never `queueRelayout()` from `refreshTables`. Source mode shows the raw pipes.
10. **Tables — editing.** Cells are edited in place and **WYSIWYG**: the field editor holds the cell's Markdown source with markers hidden and content styled (`CellMarkdown.styleSource`, restyled on every change; `allowsEditingTextAttributes`). Read the source from the field editor's string (`currentSource`, captured *before* `textDidEndEditing` calls super) — afterwards `stringValue` is the display value without the hidden markers. Selection follows **first-responder changes** (`MarkdownCellField.onFocus` → `cellDidFocus`), not `controlTextDidBeginEditing`, which only fires on the first keystroke; grips, the bar and Format → Table all use that selection. Tab / Return move between cells and add a row at the end; ↑ / ↓ move a row (header ↔ body, the delimiter row is skipped, never inserts) and ← / → cross into the neighbouring cell at the start / end of the text. **While the cursor is in a cell** two control clusters appear: in the left margin a blue row grip beside the row, a green **+** on the row's top and bottom edges (insert above / below) and a red **−** left of the grip (delete row); above the table a blue column grip over the column, a green **+** on its left and right edges (insert left / right) and a red **−** above the grip (delete column). Each **+** sits exactly where the new row or column appears (`TableCircleButton`). The header row shows only "+ below" (it never moves or goes away). Dragging a grip moves the row (header excluded) or column (alignment included) — `TableMutator.moveRow` / `moveColumn`, one undo step each, with a drop line while dragging. The chrome hangs outside the table frame, so `PagesTableView.hitTest` checks it first and `pointerHotspot` includes it. The same commands are in **Format → Table** and the cell's context menu; they act on the focused cell and are disabled outside a table (`validateMenuItem`). Every structural edit **commits the focused cell first** (commits always use `currentSource`, never the rendered text) and `applyTableEdit` detaches the editing field (`detachEditingField`) — otherwise the old field commits stale text into the new table shape when it resigns. `TableMutator.render` keeps GFM alignment colons. Table edits keep **the table** where it is on screen (`PagedEditorView.tableAnchor`, re-applied after each queued relayout pass), skip the controller's caret anchor (`isApplyingTableEdit` — the text caret may be anywhere in the document), and leave a zero-length caret so no hidden source is ever shown selected. The toolbar **Table** button (view-based, so the popover anchors under it) opens a Pages-style gallery (`TableStylePickerView`: Basic, Two Columns, Wide, Compact, Tall, Grid); one click inserts that shape with the cursor in the first cell.
11. **Format toolbar.** Heading popup, Bold, Italic, Strike, List, Link, Table, and the Code *insert* pull-down follow `MarkdownEditing.FormatState` at the caret. Code offers Inline Code, Text, Bash, Python, Swift, JSON: fence types insert an empty fenced block with the caret on the inner line (`MarkdownEditing.insertCodeBlock`), or retype the block the caret is in. A highlighted Bold click unwraps via `toggleInline`. Paragraph is heading level 0. Controls that cannot apply are **disabled**: fenced code, page-break, and thematic-break lines lock every format control. While a **table cell** is being edited the toolbar works on the cell's field editor instead (`activeCellEditor`: Bold, Italic, Strike, Inline Code, Link via `MarkdownEditing.toggleInline` / `insertLink` on the cell text; block formats disabled), and it follows the cell's selection (`NSTextView.didChangeSelectionNotification`). Inside a link label inline formatting works (`[the **docs**](url)`); inline code blocks bold/italic/strike/link (the Code pull-down stays enabled to unwrap); source-mode table cells still allow inline wraps.
12. **Headings.** Spacing is compact (AppKit does not collapse adjacent paragraph spacing). `h1`/`h2` draw a GitHub-style full-width rule in the heading's `paragraphSpacingAfter`. The blank line or setext underline under that rule is not typeable (`MarkdownEditing.snapOutOfHeadingRule`).
13. **Window chrome and sidebar (Preview parity).** The window uses `.fullSizeContentView` and its `contentViewController` is an `NSSplitViewController`: thumbnails are an `NSSplitViewItem(sidebarWithViewController:)` (150–240 pt, default 160, collapsible — below ~140 pt the toolbar pushes the thumbnails toggle into the overflow menu, so never lower the minimum), the editor column is the content item. Do **not** hand-roll the split, paint an opaque titlebar/sidebar fill, or turn off full-size content: the system sidebar item gives the full-height Liquid Glass pane (vibrant sidebar material on 14/15) with the traffic lights on it, and makes `NSTrackingSeparatorToolbarItem(.sidebarTrackingSeparator)` track the divider. The thumbnails toggle is a view-based `NSButton` (`visibilityPriority = .user`) placed before that separator, so it sits next to the window controls — also while the sidebar is collapsed. It must **not** be `isNavigational` (macOS 26 moves navigational items into the document header). The editor scroll view runs under the semi-transparent toolbar; `automaticallyAdjustsContentInsets` keeps the first page below it (same for the first thumbnail). The sidebar collapses with `NSSplitViewItem.isCollapsed` (animated, ease-in-out 0.25 s). Thumbnails keep A4 proportions, are centred, and use the **system** scroller style (never `.legacy` or a reserved gutter); the single column auto-sizes so the list never scrolls sideways. The selected page gets a light gray-blue rounded box that includes the page number. Glass KVC keys newer than macOS 26 (e.g. `effectIsInteractive`) must be guarded with `responds(to:)`. Default body text is Times New Roman 10 pt, configurable in Settings (`⌘,`).
14. **Thumbnail resizing.** Never re-render thumbnails per resize frame. Rows use a uniform `rowHeight` (no `heightOfRow` delegate). Cells are pure layers (bitmap `contents` with `contentsGravity = .resize`, selection box as a layer, shadow with an explicit `shadowPath`, no `draw(_:)`). Bitmaps are cached per page with a generation; during live resize, or less than 120 ms after a width change, they are only scaled. Afterwards visible rows re-render in ≤ 8 ms batches when the cached bitmap is smaller than the 16 pt-bucketed target or > 1.6× larger. Edits keep the old bitmap until the new one arrives. Scrolling is inset-aware so row 0 never hides under the titlebar.
15. **Zoom.** One Keynote-style pull-down (`zoomPopup`): `PageGeometry.zoomSteps` (25–400 %; ⌘+ / ⌘− step through the same list), then **Auto** (fit the page to the window; the old Fit Width and Wide modes were merged into it, and a stored `wide` migrates to `auto`). The title is **Auto** in Auto, else the live magnification as a localized percentage (no-break spaces normalized, as NSMenuItem does); the active mode or matching preset is checked. Auto refits whenever the editor's own frame changes (`NSView.frameDidChangeNotification` on the scroll view: sidebar slide, divider drag, window resize) and once more when the sidebar animation completes — do not key it off the sidebar width, which jumps to 0 before the editor grows. Every programmatic zoom goes through `setMagnification` / `applyZoomFromSettings`, which keep the **line at the top of the visible area** in place (exactly the document top when it was showing) — plain `NSScrollView.magnification` keeps the *centre*, which pushed an opened document's first page out of view. Measure the top via view-coordinate conversion (`visibleTopDocumentY`), not clip insets, and capture it **before** a settings restyle/relayout (`applySettings` passes `keepingTop`). Opening a document scrolls to the top (`scrollToTop`). Pinch-zoom ends in manual mode. Zoomed-out pages are centred with `CenteringClipView`.
16. **Tabs.** New documents open as a **tab** of the frontmost document window: `tabbingMode = .preferred`, and `DocumentWindowController.showWindow` attaches the window with `addTabbedWindow` explicitly (automatic tabbing depends on System Settings and key-window timing). `DocumentWindow` shows the native tab bar **only while a tab group has two or more tabs** (`syncAllTabBars` after add / close / move / merge / key), because AppKit otherwise remembers an explicit "Show Tab Bar" for a lone window. The View menu toggle is disabled. Never replace the system tab bar with a custom one.
17. **Launch and open.** Document windows reopen where the last one was (`DocumentWindowController.placeWindow`: frame saved on move / resize / close under `sk.lubino.marka.windowFrame`, cascaded 22 pt if another window already sits there, ignored when mostly off-screen) and are centred the first time — never AppKit's bottom-left default. No explicit "open Untitled" in `applicationDidFinishLaunching` (files from Finder arrive after it; AppKit asks `applicationShouldOpenUntitledFile` only when nothing is being opened). Opening a file while the only document is an untouched empty Untitled replaces it (`MarkaDocumentController.isPristineUntitled`).
18. **No status bar.** The toolbar `pageInfo` item (`PageNumberButton`) shows only the visible page number (Settings can hide it; ⌥⌘G still works). Clicking it, or View → Go to Page… (⌥⌘G), opens `DocumentInfoViewController` in a transient popover: editable page field + stepper (Return jumps, clamped), "This page: N words" and "Cursor on page N" when the caret is elsewhere, an optional word-goal progress bar (Settings → Word goal; 0 = off), words, characters (with/without spaces), selection, reading time, paragraphs, lines, headings, links, images, tables, code blocks, tasks, encoding, line endings, file size, modified date, saved state, and the path (wraps by character inside the 16 pt side insets) with Show in Finder / Copy Path. The popover has a fixed 320 pt width and an explicit `contentSize` from the laid-out content (an empty root frame squeezes the stack and drops the insets). Counts come from `MarkaCore.DocumentStats`, per-page ranges from `PagedEditorView.pageTextRanges()`, computed only while the popover is open.
19. **Find & replace.** The toolbar search button (view-based) and Edit → Find… (⌘F) / Find and Replace… (⌥⌘F) open `FindReplaceViewController` in a popover: find field with "n of m" and ↑/↓ (⌘G / ⇧⌘G, Return / ⇧Return), Replace (one undo step, continues to the next match), All (one undo step), Match Case, Whole Words. The popover is a two-column grid: equal-width capsule fields (Replace is a search field whose magnifier slot shows a decorative `arrow.2.squarepath` replace icon — without an icon its text sat on the field's left edge — so both texts start at the same x) and equal-width segmented controls (⌃ | ⌄ and Replace | All) sharing the right edge; focus is set *after* the popover is on screen (earlier, AppKit focused Replace). Matching is `MarkaCore.FindEngine` on the Markdown source; all matches are highlighted (temporary attributes in TextKit 1, rendering attributes in TextKit 2) and the current one is selected and flashed.
20. **Export, print, share.** PDF export draws the same pages and adds a URL annotation over every link label (`PDFExporter.linkRegions`: web links as-is, local and `.md` links as absolute file URLs; links inside tables are not annotated because tables are drawn by the overlay). Print goes through `NSDocument.printDocument(_:)` → `MarkdownDocument.printOperation(withSettings:)`: the standard print sheet with preview, copies and page range (File → Print… ⌘P and the toolbar Print button). Share uses the system `NSSharingServicePickerToolbarItem` (AppKit anchors the picker under the button) and File → Share is replaced on each menu open by `NSSharingServicePicker.standardShareMenuItem`; both share the document's `.md` file (`shareItems()`: saved documents share `fileURL`, autosaving pending edits first; untitled ones a temporary `<name>.md`). Never anchor a hand-made picker to the content view.
21. **Syntax highlighting.** `MarkaCore.SyntaxHighlighter` colours fenced code by its info string (bash/sh/zsh, JSON, Python, JavaScript/TypeScript, C/C++, Swift, HTML, XML, CSS/SCSS, YAML, Go, Rust, Java, Kotlin, Ruby, SQL, PHP). It returns non-overlapping UTF-16 ranges; `StyleEngine.highlightCode` only sets foreground colours (GitHub Primer palette, light/dark), so highlighting never changes layout. No packages.
22. **Fast, flash-free styling.** `applyStyles(range:)` restyles **incrementally**: `StyleEngine.apply(limit:)` grows the edited lines (plus one line of context each side, for setext underlines) to every span group touching them until stable, and styles only that region; edits whose old or new text contains a structural character (`` ` ``, `~`, `|` — fences, tables) restyle the whole document, because they can change blocks elsewhere. All attribute changes run inside one `beginEditing` / `endEditing` (otherwise every call is processed separately). `applyEdit` (format buttons, table and replace edits) restyles **synchronously** before the window can draw, so `**` / `*` never flash; typing restyles on the next run-loop turn. `MarkdownSyntax.parseInline` sizes its scratch array to the paragraph, never the document (that was O(paragraphs × length)). A UI test checks that every incremental restyle equals a full one.
23. **Edits never move the view.** `MarkdownTextView.applyEdit` replaces only the **changed range** (common prefix / suffix diff), never the whole text: a full replacement re-laid out the whole document, re-rendered every thumbnail and made formatting (Bold, Italic, …) shake the view for a while. `MarkdownTextView.shouldChangeText` tells the controller before every edit; it records the caret's on-screen offset (`editAnchor`) and restores it after restyle + relayout settle. `canvas.hasPendingRelayout` means another pass is *queued* — the running pass does not count, or the anchor never clears and later edits jump back to an old position; anchors also expire after 1 s. (A full restyle re-lays out from estimated heights first, which used to drift the view about a line per edit.)
24. **Undo.** `MarkdownTextView.allowsUndo` is true and uses the window `UndoManager`. Cmd+Z and Ctrl+Z both undo. Format, table, and replace edits go through `shouldChangeText` so each registers one undo unit. `applyStyles` disables undo registration so restyling is not an undo step. `setDocumentText` disables registration and clears actions with the text view as target (file open / reload). Do not mix a custom snapshot stack with AppKit `NSUndoTyping` in the same group.
25. **Empty untitled windows.** The text view is `initialFirstResponder`. Toolbar controls `refusesFirstResponder`. Typing into an empty document goes through `MarkdownTextView.insertText`.
26. **Crash reports.** `CrashReporter` installs an uncaught-exception handler and fatal-signal handlers, writes `~/Library/Logs/Marka/crash-*.log`, and on the next launch shows an alert with **Show Log**. No third-party crash service. Do not present the alert from UI tests (`MarkaRuntime.start` is the only installer). It also registers `objc_setUncaughtExceptionHandler` (chaining the previous one): exceptions thrown inside system drawing end in `std::terminate` without reaching Foundation's handler, and the log would only say SIGABRT. **Anything drawn on the paper** (code-block language label, image placeholders, alerts, tables) uses fixed paper colours (`Theme.paperSecondaryText`, `codeBlockFill`, …), never dynamic system colours like `secondaryLabelColor`: those follow the window appearance (wrong on white paper in dark mode) and resolved to nil while pages were drawn off-screen for thumbnails, which crashed CoreText ("attempt to insert nil object", 4 crashes on 2026-11-20).
27. **No WebKit.** Verify with `otool -L build/Marka.app/Contents/MacOS/Marka` — `WebKit.framework` must not appear.
28. **Math and Mermaid (native).** `MarkaCore.MathParser` turns a LaTeX math subset into a `MathNode` tree; `MathRenderer` lays it out TeX-style (atom spacing, math axis, display / text / script styles, stretched `\left…\right`, drawn radicals) on the system **STIX Two Math** font (present on macOS 14+), using Unicode mathematical alphanumerics for italic variables, `\mathbb`, `\mathcal`, `\mathbf`, …; unknown commands render red. `MarkaCore.Mermaid` parses flowcharts (layered Sugiyama-style layout: cycle breaking, longest-path ranks, barycentre ordering; back edges route around the whole chart), sequence diagrams and pie charts; `MermaidRenderer` draws them in Mermaid's default palette (dark-paper variant). Markdown: inline `$…$` (GitHub rules — no space just inside, no digit after the closing `$`, so prices stay text), display `$$…$$` (one or several lines) and ```math / ```mermaid fences, all `codeBlock(language:)` / `.inlineMath` spans. WYSIWYG: drawn blocks collapse their source like tables and reserve the drawing's height via `extraBlockSpacing`; a drawing that would cross a page break moves to the next page (`renderedPlacement`); no code chrome. Clicking a drawing opens `RenderedSourceEditor` (source + live preview; Done / click-away applies one undoable edit between the markers). Like every popover, its root is a plain container with explicit 16 pt insets and an explicit `contentSize` — an `NSStackView` root loses its `edgeInsets` and puts Done on the popover's edge. Inline math hides its source, reserves the width as kern on the closing `$`, and `MarkdownTextView` draws the formula on the baseline; with the caret inside, the source shows (incremental restyle of that line only). `$` is a structural character for incremental restyling. PDF / print draw both (`drawRenderedBlocks`, `drawInlineMathForExport`); Core Text drawing resets the text matrix, or AppKit's flipped one turns glyphs upside down. Source mode shows raw Markdown. Stretched `|` / `‖` delimiters (`vmatrix`, `\left|`) are drawn as thin rules — scaling the glyph to a delimiter's width turned it into a black block. The **Insert** menu (Table, Image…, Code Block | Equation, Matrix | Flowchart, Left-to-right flow, Sequence Diagram, Pie chart) opens `InsertGalleryView` at the caret: tiles drawn with the real renderers on paper colours (diagrams get larger tiles), templates from `MarkaCore.InsertKind`; a click applies `MarkdownEditing.insertTemplate` (block on its own lines, one undo step; code tiles insert an empty fence with the caret inside). Unit tests parse every template, so a gallery never shows red unknown commands. Format keeps its Code Block submenu; Insert Table moved to Insert → Table.

29. **Autosave and auto-load.** Settings → Autosave drives `MarkdownDocument.autosavesInPlace` (off: ⌘S saves, closing asks). Settings → Auto-load (default on): `FileWatcher` watches the open file with a kqueue vnode source and re-arms on delete / rename, because editors, AI agents and git replace files atomically; `checkForExternalChange` also runs whenever the window becomes key. Marka's own saves are recognised by their bytes (`knownDiskData`: read, written or accepted), never by timing. A different file with no unsaved edits reloads through `DocumentWindowController.reloadMarkdown` — one minimal, undoable `applyEdit` (caret mapped across the change), so the view never moves — and the document is marked clean again on the *next* run-loop turn (NSDocument counts the undo group as a change when it closes). With unsaved edits a sheet asks: Load from Disk / Keep Mine. Accepting a disk version updates `fileModificationDate`, so the next save does not raise AppKit's "changed by another application" alert.
30. **Git Publish.** Settings → Git (default on; the checkbox is disabled when no git is installed — `Git.installed` accepts Homebrew git, or `/usr/bin/git` only when `xcode-select -p` has a developer directory, because that path is a stub otherwise). `MarkaCore.Git` runs git synchronously off the main thread (`GitService.queue`, serial so ordering holds) with `GIT_TERMINAL_PROMPT=0`, `GIT_LITERAL_PATHSPECS=1`, `GIT_OPTIONAL_LOCKS=0`, Homebrew on `PATH`, stdin closed and a timeout — it must never wait for input. Paths are compared via `realpath` (`/var` vs `/private/var`; `URL.resolvingSymlinksInPath` strips `/private`, do not use it). The toolbar Publish button exists only while git is enabled (`applyPublishVisibility`) and is enabled only while the document is **tracked** (`refreshGitState`: on bind, window key, settings change, after Save As / Publish). Publish (`gatherPublishSnapshot`) saves every open document of the same work tree (always including the clicked one), `git add`s the untracked files they link to or embed inside the work tree (`Hyperlink.linkedFiles` → `GitPublisher.trackLinkedFiles`: existing files only, `#anchor` / `?query` dropped, folders, web links and ignored paths skipped, one `git add` per file), collects tracked ones plus files Marka added this session (`NewFiles`), and shows `PublishViewController` — header tile, tabs Message / Files / Diff / History (last 3 commits), Cancel and green Publish (⌘↩). `GitPublisher.publish` runs `git add` + `git commit --only` on exactly those paths (other staged work stays staged), then pushes when `origin` exists (`--set-upstream origin HEAD` without an upstream). Failures show `PublishFailureAlert` ("Publish could not be done" / "…could not be completed" when only the push failed; the commit stays) with a "Show more" link revealing git's log; fixing is left to external Git tools. **Newer published version:** once per opened document (`checkForPublishedUpdate`, Settings → "Check for a newer published version on open", default on) `GitUpdater.check` runs on `GitService.networkQueue` (fetch must never delay Publish): file tracked, branch has an upstream, `git fetch` succeeds (offline = silent), and `HEAD..@{u} -- path` has commits. A Yes / No sheet names the latest author, subject and time; Settings → "Update to it automatically" (default off) skips it. Updating saves the repository's open documents, runs `git merge --ff-only @{u}` (never a merge commit, never overwriting local edits) and reloads them with `checkForExternalChange(force: true)` — also with auto-load off; a refusal shows "Update could not be done" with the log. Files Marka creates in a work tree are `git add`ed: first saves (`save(to:…:.saveAsOperation)` to a new path), link-created `.md` files and dropped images (ignored paths fail quietly).

31. **GitHub extras (only what GitHub renders).** *Text effects:* `<ins>` (also reads `<u>`), `<sup>`, `<sub>`, `<kbd>` are inline spans (`StyleKind.underline / .superscript / .subscript / .keyboard`); only the tags are taken, so Markdown inside keeps working; WYSIWYG hides the tags (`<kbd>` tags with kern 0 — the box padding sits on the opening tag and the key's last character, and the second marker pass must not reset it), sup / sub shrink the existing font with a baseline offset in a late pass, `<kbd>` reuses the inline-code box (box height comes from the first *visible* character's font). Toolbar: the `effects` pull-down after Strike (checkmarks follow `FormatState`), Format menu items, table cells via `toggleInCell`. *Alerts:* `MarkdownSyntax.alerts` (first quote line exactly `[!KIND]`); a blank line ends a quote (CommonMark), so two alerts stay two. WYSIWYG hides the marker but keeps its line as a full-height title row; `QuoteChromeView` draws every quote's left bar (grey, or the alert colour) and the alert icon + title, on screen and in PDF. Symbols drawn into PDF go through `QuoteChromeView.tintedSymbol` (bitmap; palette configurations print as solid squares). *Anchors:* `MarkdownSyntax.headingAnchors` / `githubSlug` (GitHub rules, duplicates `-1`); `#anchor` links navigate (`MarkdownTextView.openLink` → `openAnchor`), `file.md#x` opens the file (`Hyperlink.destination` drops the fragment). `DocumentOverviewViewController` (headings + `linkableFiles`) sets a link from the link card's overview button and navigates from the page popover and the toolbar `overview` item "Content" (right after `pageInfo` "Page"; both are bordered `.texturedRounded` 24 pt buttons like Bold / Italic / Strike so they read as one group; when Settings re-adds the page control it goes before Content; View → Go to Content… ⌘L): 460 pt wide, one single-line row per item (SF Symbol, title truncated in the middle and indented 14 pt per heading level, grey right-aligned detail — `#anchor` or folder), `OverviewTableView` owns the hover (one row, from the pointer position — re-evaluated on every scroll, because rows moving under a still pointer send no enter / exit events; per-row tracking left several rows highlighted) and sets the pointing hand over clickable rows, `OverviewRowView` only draws the rounded hover fill (section titles get neither), a light accent selection, ↑ ↓ / ↩ / esc (clears the filter, then closes) and a footer behind a separator. *Image options:* images may be `<img src alt title width height align>` (optionally in `<p align="center">`, `MarkdownImage.wrapper`); `setImageOptions` writes plain Markdown when nothing special is set, else that HTML; sizes accept px / %, one value keeps the ratio; alignment moves an image-only line. *Emoji:* `EmojiCatalog` (GitHub shortcodes + emoticons, never inside code, math or link addresses); Settings → shortcodes as emoji (default off) hides the code and draws the emoji (`.markaEmoji`, width as kern) unless the caret is inside; Find & Replace's Emoji option / Edit → Replace Emojis… steps through codes and replaces them (All = one undo). *Tables:* column alignment shown (`Block.alignments`) and set (`TableMutator.setAlignment`, Format → Table → Align Column …); `MarkdownSyntax.splitPipes` keeps `\|` inside a cell, typed pipes are escaped on commit.

32. **Lists (GitHub look).** `MarkdownSyntax.listItems` gives every item its nesting level (indentation stack), kind and GitHub numbering (from the first item's number, counting up per level; a blank line does not restart an ordered list — CommonMark). WYSIWYG hides the marker (`- `, `1. `, `- [ ] ` and its indentation), indents the line by level with a hanging indent (`Theme.listIndent` / `listMarkerWidth`, width reserved as kern on the marker's last character), and `MarkdownTextView.listMarkerPlacements` draws the marker (bullets as shapes — filled circle, ring, square by level, since "•" and "◦" look alike at text size; numbers in the body font; checkboxes) centred on the x-height, on screen and in PDF. Clicking a checkbox toggles `[ ]` / `[x]` (`MarkdownEditing.toggleTask`, one undo step; pointing hand). This pass runs after the generic marker-hiding pass, which must not get list markers last. Lists inside quotes (`> - item`) are list items too (`quoteDepth`, indented from the quote's text). Done tasks are dimmed. **Editing** (`BlockEditing.swift`): `setList` / `toggleQuote` act on every selected line (indentation and quotes kept, numbers 1, 2, 3 per level, same kind again removes; one line keeps the caret on its letter); Return continues with the same indentation, a ticked task as unticked, a list inside a quote inside the quote; `backspaceStructure` at an item's text start outdents, then turns the item into text, and removes one quote level; the caret never stops inside a hidden prefix (`hiddenLinePrefixes` — list markers and quote markers; moving left from the text jumps to the previous line). Toolbar: a List pull-down (bulleted / numbered / task, icon follows the caret) and a Quote toggle.

## Build, test, release

```bash
# Unit tests (must pass before every commit)
swift run MarkaTests

# Off-screen AppKit UI tests (sidebar, code chrome, tables, links)
swift run MarkaUITests

# Ad-hoc signed app → build/Marka.app
./scripts/build-app.sh

# Install that build into /Applications and launch it
./scripts/install-local.sh

# Universal DMG + ZIP + checksums → build/
./scripts/package-dmg.sh

# GitHub Release from this Mac (tags exist; Actions often fail before upload)
./scripts/publish-release.sh --tag vX.Y.Z
./scripts/install-git-hooks.sh   # once per clone: tag push publishes in the background
```

SwiftPM's default build backend stamps the binary with `sdk 14.0` (the deployment target), which makes macOS 26+ run Marka in the pre-Liquid Glass compatibility look. `scripts/build-app.sh` re-stamps `LC_BUILD_VERSION` with the real SDK via `vtool` and fails if that did not work. Check with `xcrun vtool -show-build build/Marka.app/Contents/MacOS/Marka`. Note: `swift run MarkaUITests` binaries keep the 14.0 stamp, so UI tests exercise the compatibility appearance.

**App icon.** `scripts/generate-icon.swift` is the single vector source (1024 canvas): a thick rounded slab of **clear glass** (bright rim, diagonal reflection, soft caustic) with a big **"Marka"** in Arial Bold across the top (glyph outlines, fitted to the text column), two full-width bars, then two short bars at the bottom left with **"MD"** (Arial Bold, exactly as tall as those two bars) at the bottom right. Few, thick bars (50 units). Text and bars are **flat** solid `#505E76` — no shadow, no gloss, no glass accents — so the icon stays crisp and readable at small sizes; the Icon Composer groups have `glass: false`, `specular: false` and shadow `none` for the same reason. It renders the flat `AppIcon.icns` fallback — the plate must stay **opaque** and fill the standard 824 pt rounded square (100 pt margin, 185.4 pt radius): macOS 26 uses a flat icon as its own plate only when it conforms, otherwise it puts the whole icon onto a second, system-drawn plate ("two glasses"). With `--icon Resources/AppIcon.icon` it rewrites the committed Icon Composer bundle (light glass fill; Wordmark and Bars are opaque glass groups, Glass bars translucent); `--preview <png>` writes a 1024 px preview. Re-run it after changing the design. `build-app.sh` compiles the bundle with Xcode 26+'s `actool` into `Assets.car` + `CFBundleIconName` (Liquid Glass on macOS 26+; layered vector groups). It uses the active toolchain's `actool`, else any `/Applications/Xcode*.app` via `DEVELOPER_DIR` — the Swift build itself stays on the Command Line Tools, so `xcode-select` need not change (the Xcode license must be accepted once: `sudo xcodebuild -license accept && sudo xcodebuild -runFirstLaunch`). Without any Xcode, builds ship only the flat `.icns`. Opening the bundle in Icon Composer is the way to tune glass, shadows, and translucency.

**Command line.** `MarkaLauncher/main.swift` runs `MarkaCommandLine.run` first: `-pdf <in.md> [out.pdf]` (also `--pdf`; `-h` / `--help`) exports with `.prohibited` activation (no Dock icon, no menu bar) through `DocumentWindowController.loadForExport` — no document is bound, so no git checks, no file watching, and the window is never shown or moved (that would overwrite the saved window frame) — then `PDFExporter.write`, and prints the Page popover's counts (`DocumentStats`, page count). Exit 0 / 1 error / 2 usage; any other arguments (Finder, Xcode's `-NS…`) start the app. `DocumentStats` counts `<img>` tags as images too.

**File menu.** Export PDF… and Publish… carry the toolbar's symbols (`menuSymbol`, macOS 14 fallbacks) and call `NSMenuItem.showsImage()`: macOS 27 decides menu image visibility itself and usually hides images (it kept only Print and Share), so `preferredImageVisibility = .visible` is set — via KVC, because the property only exists in the macOS 27 SDK and CI builds with an older one. File → Share's picker gets `MenuShareAnchor` as delegate so a chosen service opens under the toolbar Share button (found by its tooltip; else under the toolbar's middle) — from a menu it otherwise has no anchor. The toolbar share item is untouched.

**User guides** live in `documents/` (only README.md and AGENTS.md stay in the root; README's *Documents* table says why to read each). `Help.md` and `Shortcuts.md` are copied into `Contents/Resources`; Help → Marka Help (⌘?) / Keyboard Shortcuts open a fresh read-only copy from `~/Library/Application Support/Marka/Help` (GitHub `documents/…` page when not bundled). The tutorial `documents/Marka.md` + `documents/assets` is bundled as `Resources/Tutorial` and opened by Help → Marka Tutorial as a **writable** copy in `~/Library/Application Support/Marka/Tutorial` — refreshed (`AppDelegate.copyMerging`, never deleting) only while its Marka.md equals the last bundled one, so experiments and files made while trying it survive; `package-dmg.sh` puts it in a "Marka Tutorial" folder next to the app. The tutorial shows the app's **real icons** (PNG exports in `documents/assets/icons`, regenerate with `MARKA_EXPORT_ICONS_DIR=documents/assets/icons swift run MarkaUITests`) in table cells — never emoji look-alikes. Keep all guides in sync with features and menus.

Never commit secrets, `.DS_Store`, or build artifacts (`/.build`, `/build`, `*.app`, `*.dmg`).

GitHub Actions:

- `.github/workflows/ci.yml` — on push/PR: tests + `Marka.app`; on `main` also packages DMG/ZIP as artifacts.
- `.github/workflows/release.yml` — on tag `v*` (and workflow_dispatch): tests, universal package, GitHub Release assets (`Marka.dmg`, `Marka-macos.zip`, `SHA256SUMS.txt`). If that job fails (common: UI tests are errors on the GitHub macOS runner), publish from this Mac with `scripts/publish-release.sh`. A `pre-push` hook in `.githooks` starts that script after a `v*` tag is pushed.

## After any code change (local install)

The maintainer wants the **installed** app to match the working tree after every Marka change, without waiting for push.

1. Run `swift run MarkaTests` and `swift run MarkaUITests`.
2. Run `./scripts/install-local.sh` (builds `build/Marka.app`, replaces `/Applications/Marka.app`, launches it).
3. Do **not** skip the install because the user still has an old `build/` binary open.

This is separate from GitHub Release. Push/tag only when the user says **push**.

## Maintainer push protocol

When the user says **push**:

1. Run `swift run MarkaTests` and `swift run MarkaUITests`. Confirm `git status` / `git diff` contain no secrets or build artifacts.
2. Patch-bump `VERSION` (MAJOR.MINOR.PATCH).
3. Stage intended files, commit in English (what + why), `git push origin main`.
4. Tag SemVer (`git tag vX.Y.Z && git push origin vX.Y.Z`). The `.githooks/pre-push` hook then runs `scripts/publish-release.sh` so GitHub gets `Marka.dmg`, `Marka-macos.zip`, and `SHA256SUMS.txt` even when `release.yml` fails. If the hook is not installed, run `./scripts/install-git-hooks.sh` once, or `./scripts/publish-release.sh --tag vX.Y.Z` after the tag push.
